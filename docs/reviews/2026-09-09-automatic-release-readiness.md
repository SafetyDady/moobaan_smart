# ชุดพร้อมรีวิวก่อน release: กระทบยอดอัตโนมัติและสิทธิ์อ่านใบแจ้งหนี้

**สถานะ ณ 9 ก.ย. 2026 เวลา 14:40 น.:** ตรวจรับ Local เสร็จ สำรอง DB สดและกู้คืนตรวจแล้ว ยังไม่ commit / push / deploy และยังไม่ซ่อมการผูกยอดย้อนหลังใน production

ฐานโค้ด/rollback ปัจจุบัน: `f3221398d46d16bf4289e9236962e179193c3738`

## สิ่งที่จะขึ้นใน release นี้

1. ใช้เงินยืนยันที่ยังเหลือของบ้านอัตโนมัติเมื่อรับเงินหรือสร้างบิล เรียงเงินตามเวลารับจริงและบิลตามวันครบกำหนด ใช้ transaction/locks ร่วมเพื่อกันใช้เงินซ้ำ ลูกบ้านไม่มีสิทธิ์เลือกบิล
2. ปิดช่องอ่านใบแจ้งหนี้โดยไม่ล็อกอิน และจำกัด resident ให้อ่านเฉพาะบ้านที่เลือกใน session และยังเป็นสมาชิกที่มีสิทธิ์ รายการเงินสำหรับเลือกชำระให้ Admin/accounting เท่านั้น
3. เพิ่ม regression tests และ context/review documentation

ไม่มี migration, frontend, dependency หรือ startup job ใหม่ ไม่รวม Local test harness, credentials, DB dumps หรือรูปสลิปใน Git

**ผลกระทบที่ต้องอนุมัติ:** deploy เองไม่กวาดยอด แต่การยืนยันเงิน/สร้างบิลครั้งถัดไปจะนำเงินเก่าที่ยังเหลือของบ้านไปชำระบิลค้างด้วย กรณีสร้างรายเดือนทั้งหมู่บ้านจึงมีผลหลายบ้านตาม policy นี้ ไม่มีการกลับรายการหรือย้ายประวัติเดิมเอง

## หลักฐานตรวจรับ

**101 regressions ผ่าน** (74 PostgreSQL + 27 status/date/export) รวม 20 cases ที่ทดสอบรอล็อกจริง ผลนี้อ้างโค้ด application/test ที่ hash ยังตรงชุด Local UI ก่อนรอบตรวจรับ ไม่มีการแก้ application code ในรอบ readiness นี้

เพิ่มการทดสอบ lifecycle ผ่าน HTTP server ที่รันจริงบนฐานสำเนาแยกอีกชุด **9 สถานการณ์ผ่าน**:

| สถานการณ์ | ผลที่ตรวจ |
|---|---|
| รับเงินก่อนสร้างบิล | เงินเหลือถูกนำมาชำระเมื่อสร้างบิล |
| ยืนยันรายการเดิมซ้ำ | ตอบ already_posted; hash DB ไม่เปลี่ยน |
| สร้างบิลก่อนรับเงิน | ยืนยันเงินแล้วบิลชำระอัตโนมัติ |
| เงินล่วงหน้า 1,500.24 บาท | ลงสามบิล 600 / 600 / 300.24 ไม่ใช้เงินเกิน |
| บิล 600 ชำระ 200 แล้วลดเต็ม | ลดเฉพาะ 400 ที่ค้าง; กดซ้ำไม่ลดเพิ่ม |

| เงินเก่าเหลือร่วมกับเงินใหม่ | ใช้เงินเก่าก่อน; รายการผูกเดิมไม่เปลี่ยน |

ใช้บ้านและ Statement/Pay-in จำลองที่ระบุ SYNTHETIC LOCAL TEST ชัดเจน เพื่อเรียก financial writer ผ่าน HTTP; ไม่ใช่การนำรายการธนาคารจริงไปยืนยันซ้ำ ไม่ใช่การทดสอบ upload/parser/LINE/R2 ครบวงจร

ตรวจแล้วทุกแถวเดิมของข้อมูล 157 บ้านในสำเนายังคงอยู่เหมือนเดิม ฐานหลักฐานต้นทางยังตรงทั้ง 26 ตาราง และฐาน Local ที่เจ้าของเปิดอยู่ไม่เปลี่ยนจากการทดสอบนี้ ปิดเฉพาะ server ตรวจรับแยกพอร์ต 8011 แล้ว; หน้าเจ้าของพอร์ต 5175 ยังเปิดอยู่

ผล HTTP ชุดก่อนหน้าครบบ้าน: สร้างกันยายน 157 บิล / 313 allocations / ใช้เงินเพิ่ม 181,012.56 บาท; สร้างซ้ำ 0 บิล; Admin/resident 28/95 เห็นข้อมูลใบแจ้งหนี้ตรงกัน; เนื้อหารายงานเงินรับพฤษภาคมทุกบ้านเท่าเดิม

## ขอบเขตและเงื่อนไข release

- ยังไม่ย้ายประวัติ 28/95 หรือบ้านอื่น การซ่อมเก่าต้องจัด before/after จากข้อมูลล่าสุดเป็นอีกชุด
- ไม่มีคำรับรองว่าระบบทุกส่วนไม่มีบั๊ก: ตรวจเฉพาะ flow/สิทธิ์ที่ระบุ ไม่รวม LINE OAuth จริง รูป R2 และการแข่งขันกับการปิดงวดบัญชี
- ก่อน push: ตรวจว่า Git HEAD/remote และ source hashes ยังตรง candidate, ตรวจ seed/reset ยัง false, ตรวจ backup/current data อีกครั้ง; หาก code/data เปลี่ยนต้องประเมินส่วนที่กระทบก่อน
- หลัง owner อนุมัติ commit/push: ตรวจ Railway/Vercel deployment ของ commit เดียวกัน, health/ready, anonymous/other-house access และหน้า Admin/resident จริง การตรวจ production เริ่มด้วย read-only; ไม่สร้างบิลหรือยืนยันเงินจริงเพื่อทดสอบโดยไม่ได้ระบุรายการ
- หาก rollback โค้ด ให้ย้อนเฉพาะ commit release และคง seed/reset false; **ไม่ restore DB เก่าทับ** เพราะอาจลบธุรกรรมหรือสมาชิกใหม่ โค้ดย้อนกลับไม่ย้อน allocation ที่เกิดหลัง deploy การแก้ allocation ใช้รายการชดเชยที่เก็บ audit
